Local first

Your data stays with you

History and reports stay on your own hardware. Modem data, logs, credentials and tokens are never uploaded automatically, and optional integrations only talk to the services you configure.

Reports and exports are built locally. Review them before you share them: they can contain connection details and notes.

Is it for you?

Built for cable problems that come and go

Use DOCSight if

  • your connection drops or slows down at certain times
  • video calls freeze or games lag in the evening
  • signal values look suspicious and you want a history
  • support keeps saying the line is fine and you need evidence

Look elsewhere if

  • you only need uptime alerts for websites
  • you want a public status page or a managed cloud service
  • you expect a tool to fix the line: DOCSight documents the problem, your provider fixes it

Get started

Start with the demo, then connect your own modem.

Try the demo

Realistic history with synthetic data, no modem required.

docker run -d --name docsight-demo \
  -p 8765:8765 -e DEMO_MODE=true \
  ghcr.io/itsdnns/docsight:stable

Connect your modem or router

Configuration and history stay in the docsight_data volume.

docker run -d --name docsight \
  --restart unless-stopped \
  -p 8765:8765 \
  -v docsight_data:/data \
  ghcr.io/itsdnns/docsight:stable

Then open port 8765 on that machine in your browser. The setup asks for your connection type, finds the modem on request and tests the connection.

Installation guide Docker Compose Windows quick start Windows Desktop Preview

The Windows Desktop Preview is an unsigned portable build for short local tests. For continuous monitoring, run Docker on an always-on machine.
